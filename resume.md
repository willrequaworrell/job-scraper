# Candidate Profile

## Summary

Will Worrell is a frontend-leaning full-stack software engineer based in the Greater Boston area. His strongest current fit is for product-oriented engineering roles centered on React, TypeScript, and modern web application development, especially when the work combines user-facing frontend ownership with enough backend scope to contribute across the application stack.

He has real software engineering experience across frontend development, internal tooling, AI-assisted product work, and application-focused backend work. His background also includes technical project management and business analysis, which adds product judgment, communication strength, and SDLC maturity, but those experiences should support his engineering profile rather than redefine it.

## Core Strengths

- React and TypeScript application development
- Modern frontend architecture with strong UI and component thinking
- Next.js, responsive web implementation, and user-facing product development
- Full-stack application work with Node.js APIs and typed backend logic
- Practical AI feature development and AI-assisted workflows inside software products
- Python automation and internal tooling when the problem is a good fit for lightweight scripting

## Strong Differentiators

- Thoughtful product and UX judgment, especially around clarity, usability, and visual composition
- Comfort translating between technical and non-technical stakeholders
- Modular code design and pragmatic MVP instincts
- Ability to contribute across implementation, coordination, and delivery without being a pure PM profile

## Target Role Family

- Frontend-leaning full-stack engineer
- Frontend engineer or web engineer
- Full-stack engineer with clear frontend ownership
- AI application engineer focused on building AI features into products
- Product-minded builder roles where the center of gravity is shipping software, prototypes, workflows, or user-facing product experiences

## Preferred Role Shape

- Best fit when frontend technologies are explicitly named, especially React, TypeScript, Next.js, modern CSS, design systems, or user-facing product ownership
- Good fit for balanced full-stack roles when the work is still clearly application-focused rather than backend-specialist
- Good fit for product engineering teams at any company stage when the work centers on shipping software for users
- Best fit when the role rewards product sense, communication, and UX sensitivity in addition to implementation skill
- Builder-style roles are in scope when they still require real implementation judgment, product taste, and end-to-end software shipping rather than pure evangelism or non-technical community work

## Seniority Target

- Sweet spot is junior-to-mid level software engineering
- Most competitive for Software Engineer, Frontend Engineer, Web Engineer, and Full-Stack Engineer roles
- Senior titles should usually be treated cautiously unless the scope is unusually accessible and strongly aligned with frontend product work
- Roles requiring 0 to 3 years of experience are fully in scope and should not be penalized for having a low minimum
- Treat 4+ years of required experience as a meaningful negative signal and usually a poor fit unless the rest of the role is unusually accessible
- Explicit senior, staff, principal, lead, or architect framing should be treated as strongly negative evidence even when some technologies overlap

## Geography And Working Model

- Greater Boston / Massachusetts local or hybrid roles are a strong fit
- Cambridge, Somerville, Brookline, Waltham, Watertown, Newton, Needham, Quincy, and similar Greater Boston locations should be treated as local fits, not relocation concerns
- US remote roles are in scope
- Local, hybrid, and remote roles are all acceptable; remote should not be treated as a preference over local or hybrid
- Roles restricted to non-US geographies are a poor fit

## AI Positioning

- AI is a meaningful strength when the role involves building application-layer AI features, workflows, or product experiences
- Good fit for teams integrating LLM-powered functionality into software products
- Not a strong fit for ML research, model training, deep data science, or infra-heavy AI platform roles

## Experience Framing

- Finderly should be treated as the clearest signal of direct software engineering fit, especially for product work, AI-related application features, TypeScript backend contributions, and React Native or frontend-oriented implementation
- L3Harris should be treated as valuable supporting evidence of technical maturity, tooling work, documentation systems, monitoring or operations support, cross-functional delivery, and pragmatic execution, even though it is not purely a software engineering role
- Earlier experience in business analysis and adjacent technical work supports communication, systems thinking, and delivery discipline, but should not outweigh the engineering profile

## Signals To Reward

- React, TypeScript, Next.js, JavaScript, HTML, CSS, Tailwind, design systems, frontend architecture, accessibility-minded UI work, and product-facing web engineering
- Full-stack application engineering where frontend ownership is real and backend work is primarily in service of product features
- Node.js, typed APIs, application logic, and software product development
- AI-enabled product features, context management, intelligent workflows, or application-layer LLM use
- Roles that value usability, thoughtful implementation, and cross-functional collaboration
- Product-builder language, prototyping, 0-to-1 product work, rapid iteration, and software roles that reward strong product judgment

## Explicit Anti-Targets

- Internship roles
- Backend-specialist roles with little or no frontend ownership
- Infrastructure, platform, DevOps, SRE, distributed systems, data engineering, or other infra-heavy roles
- PM, TPM, delivery-management, or business-analyst roles where engineering execution is not the main function
- ML research, pure data science, or highly specialized AI infrastructure roles

## Calibration Notes

- This profile should be read as direct and calibrated, not aspirational
- The candidate is broad enough for frontend-centered full-stack product work, but not a strong match for roles whose center of gravity is backend specialization or people/process management
- When in doubt between a product-facing frontend or full-stack role and a backend- or management-heavy role, the product-facing engineering role is the more accurate fit
